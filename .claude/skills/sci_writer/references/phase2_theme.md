# Phase 2 详解：主题与创新点评审团

## 为什么要用多提案人 + 多评审，而不是自己直接定题目

单一视角容易系统性地漏掉某类问题：一个统计学出身的人不容易发现"这个框架在期刊编辑眼里像企业软文"，一个只关心新颖性的人不容易发现"这个估计量的标准误被低估六倍"。多个**互不知情**的独立提案人和评审,是唯一能在合成前把这些问题都暴露出来的办法。压缩这一步（比如自己想一个题目就开始写）几乎总会在 Phase 4/5 才发现致命缺陷,届时返工成本高得多。

## 1. 写 BRIEF.md

提案人不应该重新读一遍全部证据文件——那样四个提案人会各自用不同的方式重新发现同样的问题，且容易读漏。把 Phase 1 的产出浓缩成一份简报：

- 硬约束（案例主体、目标期刊分区要求、必须是研究型论文、数据只能用已确认可得的、必须客观呈现负面事实）
- 已建成的核心数据集（字段、覆盖率、样本量）
- **主协调者自己先跑的探索性统计结果**（见下条）
- 必须诚实处理的限制清单
- 竞争性文献警示（已知的"占位"研究，见下节）
- 期刊候选清单初步印象

## 2. 主协调者先动手跑探索性分析

不要空手等提案人生成好结果。如果有定量数据，自己先用 pandas/统计模型跑几个最直接的假设（时间趋势、分组差异、简单相关），把结果写进 BRIEF。这样：
- 提案人能在真实信号基础上设计方案，而不是纯粹空想
- 后续评审有具体数字可以复核，而不是只能评估"听起来是否合理"
- 你自己也会提前发现数据的怪癖（异常值、编码问题、共线性），这些迟早要处理，越早发现成本越低

## 3. 竞争性文献警示

在派提案人之前，先用学术检索工具查一遍"是否已经有人做过这个明显的角度"（比如"该行业的产品/服务属性长期趋势"这种最容易想到的框架）。如果已有占位文献，写成 `NOVELTY_ALERT.md` 让所有提案人和评审都看到，避免大家撞向同一个已被占据的角度、或者更糟——设计出来的方案自己没发现已被占位,直到评审阶段才被戳穿。

## 4. 派 3–5 个独立提案人

每个提案人从**明显不同的学科/框架角度**切入（例如：本学科技术角度、产业组织/经济学角度、政策评估角度、机制整合角度——具体分几个、分哪几个角度取决于案例本身适合哪些框架）。

每个提案要求包含：
- 英文/中文题目、一句话论点、英文摘要（约 250 词）
- 研究问题（≤3 个）
- **创新点 3 条，每条必须写明"相对哪篇最接近的文献新"**，并要求提案人**实际用学术检索工具核实该文献是否存在、内容是否真如你以为的那样**（不能凭直觉断言"目前无人做过"——这是最常见的失败模式，新颖性评审阶段几乎总能戳穿凭空断言的创新点）
- 数据方案（变量、来源、样本量、缺失处理）——只能用 Phase 1 已确认可得的数据
- 方法（模型设定、稳健性检验清单）——必须与数据结构匹配（面板/横截面、聚类标准误、多重比较校正）
- **要求提案人实际运行统计代码**验证可行性与初步结果，如实报告（包括不支持假设的结果）
- 预期图表清单（≥6）
- 目标期刊候选
- 可行性与新颖性自评分（1–10）
- 风险与对策，尤其是"单一案例的一般性"这类几乎必然被审稿人质疑的问题

## 5. 派 3 个视角不同的评审

建议的三个视角（可按案例调整）：
1. **期刊编辑视角**：范围契合、读者兴趣、"是否像宣传"风险、一般性、可读性、伦理与数据来源合规性
2. **数据与统计视角**：**必须亲自动手复核**——独立重跑提案里的关键估计量（用不同子集、不同口径），检查缺失是否两臂平衡、多重比较是否处理、样本量是否真的支持声称的检验力
3. **新颖性与文献视角**：**必须亲自用学术检索工具核实**每条创新点最接近的文献是否真的存在、内容是否如提案所说，给出"审稿人最可能用来否定这条创新点的一句话"

评分维度建议：novelty、feasibility、fit（与目标期刊/分区契合度）、rigor、generality，加权求和（可行性权重通常应最高，因为不可行的方案无论多新颖都没用）。

**统计视角的复核不是走过场**：安排它去真正重新计算提案声称的数字，用不同的稳健性设定检验。这一步的价值在于——提案人往往在压力下会把探索性结果的不确定性"抹平"，独立复核经常会发现声称的效应量对某个非随机缺失的子样本极度敏感，或标准误被严重低估。这是多评审设计里最容易漏做、但性价比最高的一步。

## 6. 主协调者合成

读完全部方案与评审后，**再做一次自己的独立复算**去验证评审之间的分歧点（比如两个评审对同一个估计量给出不同判断时，谁对）。然后产出：

- `plan/00_decision_log.md`：评审汇总表、被否方案的**具体**原因（引用评审给出的数字，不要泛泛而谈）、从被否方案里嫁接进最终方案的具体要素、期刊决策及理由、待人工确认事项
- `plan/01_theme_and_innovation.md`：最终题目、一句话论点、英文摘要草稿（含识别论证——预测两种假说下的结果应该长什么样，实测结果落在哪一种）、研究问题、创新点（含完整引文）、**本文不主张的事项清单**（明确写出哪些说法是禁止出现在正文的，防止 Phase 4 写作时"顺手"升级表述）
- `plan/02_research_route.md`：变量定义表、样本与分层、模型设定（含如何避免变量间共线等技术细节）、稳健性检验清单（≥10 项）、论证地图（claim→证据→已知反证）、章节契约、图表清单、风险登记、数据采集与分析任务分解

## 常见的合成陷阱

- **把"最高分方案"直接采纳而不做整合**：评审经常会发现某个非最高分方案里有一个值得嫁接的要素（比如更好的稳健性检验设计），不要浪费。
- **对评审揭示的问题打折扣**：如果统计评审证明某个核心估计量不稳健，不能因为"这是最有意思的角度"就保留原表述，必须相应降级（改成稳健性小节、或改用更保守的替代指标）。
- **合并多个方案却没解决它们之间的张力**：如果两个方案共享同一个数据来源却对同一部分方差给出不同解释，合并成一篇论文前必须先解决这个张力，否则读者会立刻发现自相矛盾。
